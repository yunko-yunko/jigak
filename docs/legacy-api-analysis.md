# 기존 서버 기능과 이관 계약

분석 대상은 `C:\jigak_old\perception-map\mvp\server`다. 요청에 적힌 `perception-map/server`는 실제 저장소에서 `mvp/server`에 있다. HTTP 진입점은 `app.ts`, `auth/router.ts`, `intelligence/learning-service.ts`이고 총 32개 HTTP 메서드/경로 조합을 제공한다. 모든 시간은 epoch milliseconds이며, 오류 형식은 `{ "error": { "code": "...", "message": "..." } }`다.

공개 조회는 기본 IP별 분당 60회, 경로 조회 두 별칭은 공유 IP별 분당 30회다. 오류 시 Retry-After가 설정된다. 기존 구현은 프로세스 메모리 제한이므로 Cloud Run 다중 인스턴스에서는 DB 원자 연산으로 공유해야 한다.

경로 요청은 `origin`, `destination`, `deadline`, `now`, `preferences`, 선택 `purpose=search|urgent|replan`이다. Place는 id/name 각 1~300자, address 최대 500자, 위도/경도, 선택 note 최대 1000자다. preferences는 walkingOnly?, allowRunning, allowBicycle, maxRunningMeters(정수 0~5000), maxBicycleMeters(정수 0~10000), runningPace(easy/steady), preparationSeconds(정수 0~3600), bicycleReady, allowTaxi?, allowScooter?, hasCar?, carLocation?를 받는다. 모든 객체는 알려지지 않은 필드를 거부한다. 일반 검색 마감은 서버 현재보다 미래이고 48시간 이내, urgent/replan은 서버 현재의 ±48시간 이내다. 기기 now는 서버와 120초 이내여야 하고 출발/목적 좌표가 같으면 거부한다. 걷기 전용이 아닌데 달리기/자전거를 허용하면 해당 최대 거리는 0보다 커야 한다.

경로 엔진은 보행망과 Kakao 대중교통 기본 후보를 구하고 실시간 승차, 발행 시간표, 역 환승 참조, 보행 진입/이탈을 결합한다. 중간역 탐색, 도보/달리기 변형, 택시·자가용·대여 자전거·킥보드 연결, 실제 주차장, 도로 상황, 날씨를 반영해 여정 그래프를 탐색한다. 검증되지 않은 보행 연결·대여 재고·영업/운행 종료 정보는 추천 적격성과 불확실성에 반영한다. ETA 보정, contextual 모델, public bus 모델, 전체 여정 위험 모델을 적용한다. 한 요청의 초기·재시도·정교화 호출은 동일 CallBudget을 사용한다. 결과는 intelligence, rentalAvailability, search 최적성/불완전 사유, notice, requestId, providerCalls, routeCallBudget, failures를 포함한다. gzip 협상, Server-Timing, 연결 해제 감지, 개인정보 없는 숫자 성능 계측도 제공한다.

인증 start/callback/exchange, 계정 삭제, 문의는 IP별 15분당 60회를 공유한다. Bearer 세션은 43자 난수이며 DB에는 해시만 저장한다. 웹 세션은 `/api` 경로, HttpOnly, SameSite=Lax, HTTPS 앱 주소일 때 Secure 쿠키다. 쿠키 인증의 변경 요청은 정확한 허용 Origin과 X-CSRF-Token 모두를 요구한다. Apple form_post의 CORS 예외는 해당 callback 폼에만 적용하며 다른 API의 읽기 권한을 제공하지 않는다.

세션 7일·최대 활성 20개, OAuth state 5분, auth_ticket 2분·단회·클라이언트 PKCE 바인딩, 미동의 계정 24시간, 문의 90일 보존이다. 동일 이메일을 가진 다른 공급원 식별자는 자동 병합하지 않는다. OAuth grant와 임시 state는 AUTH_TOKEN_ENCRYPTION_KEY를 이용해 AES-256-GCM 암호화한다. Google/Apple ID JWT는 고정 HTTPS JWKS, RS256 서명, issuer/audience/만료/iat/nonce를 검증하고 Google azp도 검사한다. Kakao는 서버 user/me 응답을 식별 근거로 쓰고 OIDC 설정 시 JWT도 검증한다. Apple 이름 정보는 표시용이다. 공급원 미설정 상태에서 가짜 로그인 성공을 생성하지 않는다.

## 비HTTP 기능과 의존성

`connectivity/`는 OSRM 보행망 경로, 요청 내 동일 조회 재사용, 역별 환승 CSV 참조다. `realtime/`는 서울 실시간 지하철·버스, 공휴일 서비스 달력, 시간표, 서울 도로, 공공 자전거, TAGO/GBFS 킥보드, 공공 주차, 기상청을 통합한다. `intelligence/`는 보정값 검증, 구간/여정 ETA 특징과 학습, public bus 운영 모델, bicycle shadow 모델, 공간·이력 모델, GBFS 허용 정책, 관측 수집/자동 학습이다. 모델 생성·공공 자료 refresh는 HTTP 관리 엔드포인트로 노출되지 않으며 운영 작업으로 분리한다. supplier-http는 HTTPS 고정 공급원, timeout/응답 크기/에러 정규화, query reuse와 호출 예산을 담당한다.

서버만 복사해서는 동작하지 않는다. `mvp/src/domain/`의 types/index/routing/estimatedTiming/subwayTimetable/vehicleConstraints/routeEffort/waitEstimates/routeIdentity/nearbyTransit/mobilityPreferences와 `src/intelligence/`의 types/learning/journeyLearning/journeyRisk/timing/rentalAvailability, `src/journey/realtimeFreshness.ts`가 필요하다. 도메인 계층은 UI 의존 없이 가져올 수 있다. 환승 CSV/metadata와 공휴일 JSON도 배포 이미지에 포함해야 한다.

기존 영속 계층은 SQLite `accounts.sqlite`, `eta-observations.sqlite` 및 로컬 JSON 모델 파일이다. Cloud Run은 파일시스템이 일시적이므로 계정·인증 state/ticket·세션·문의·학습 관측·서명 secret·모델과 무효화 세대를 Cloud SQL PostgreSQL에 저장해야 한다. 여러 인스턴스 간 단회 소비, 20개 세션 상한, 수집 중복/삭제·모델 무효화, DB 기반 속도 제한은 원자 연산/트랜잭션이 필요하다.

## 현재 영속성 구현

기존 서버 분석에 나온 SQLite/직접 SQL 저장소는 현재 구현의 실행 경로가 아닙니다. 새 서버는 TypeORM EntitySchema, Repository/QueryBuilder, EntityManager 트랜잭션을 사용합니다. 기존 테이블과 API 계약을 유지하며 런타임 동시성은 ORM pessimistic 행 잠금으로 조정합니다. 스키마 변경은 명시적인 TypeORM 마이그레이션으로만 적용하고, 옛 SQL 파일은 기존 DB의 checksum을 검증하는 보관본으로만 읽습니다.
